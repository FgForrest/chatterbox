# Localization, product naming, docs pages

The app ships in English (`en`) and Czech (`cs-CZ`). Every user-facing string exists in both.

## Strings

- User-facing strings go through next-intl's extraction API: `useExtracted()` in components,
  `getExtracted()` on the server. Messages live in `messages/en.json` and `messages/cs-CZ.json`
  under hashed keys; e-mail strings in `messages/email/`.
- After adding or changing strings, regenerate the keys. `pnpm dev` and `pnpm build` extract on their
  own but need the user's go-ahead, so run the extractor directly from the repository root with a
  throwaway file (it must sit in the repository so `next-intl/extractor` resolves; delete it
  afterwards):

  ```js
  // extract-messages.tmp.mjs
  import { unstable_extractMessages } from "next-intl/extractor";
  await unstable_extractMessages({
      srcPath: "./src",
      messages: { path: "./messages", format: "json",
                  locales: ["en", "cs-CZ"], sourceLocale: "en" },
  });
  ```

  `sourceLocale` goes inside `messages`. New keys land in `cs-CZ.json` as `""`: fill every one
  (`src/tests/i18n/localization.test.tsx` fails on an empty Czech value), then
  `pnpm format-and-lint:fix`.
- A change to `messages/*.json` reaches tests outside the import graph: run the whole suite locally.

## Product naming

- English copy says **Chatterbox**. Czech copy says **Klepna**, declined as Czech grammar needs
  (Klepna, Klepny, Klepně, Klepnu, Klepnou: "Cílová složka v Klepně", "Propojte rozšíření s
  Klepnou"), never "Chatterbox". This covers `messages/cs-CZ.json`, `messages/email/cs-CZ.json`,
  `extensions/recorder/_locales/cs` and the `.cs-CZ` docs pages.
- Shared code never writes a brand literal; the name depends on the deployment. Server code uses
  `deploymentProductName(locale)` (`src/lib/deployment-brand.ts`), client code `useProductName()` /
  `useHostedDeployment()` (`src/components/product-name-provider.tsx`). Self-host shows
  Chatterbox/Klepna; hosted shows Riffado. `src/tests/i18n/self-host-branding.test.ts` guards it.
- Mynah and other upstream service names appear only on hosted paths. `IS_HOSTED`-only landing,
  legal, pricing, changelog and billing copy describes upstream's hosted service and keeps its
  naming.
- Upstream Riffado attribution, author names, copyright notices, license text and historical
  issue/PR links stay as they are (`AGENTS.md` § Style).

## Docs pages

- Every page under `content/docs/` (the user guide, self-hosting docs, guides and reference, served
  at `/docs` and in the in-app help drawer) has an English file and a `.cs-CZ` twin, and every
  `meta.json` a `meta.cs-CZ.json`. Change both.
- User-guide screenshots are retaken with the demo stack in `docs/user-guide/demo/` (see its
  README); an image the guide references must exist before an image build.
