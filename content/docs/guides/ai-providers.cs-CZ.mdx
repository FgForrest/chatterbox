Chatterbox využívá OpenAI SDK s konfigurovatelnou `baseURL`. Jakýkoliv poskytovatel,
který nabízí OpenAI-kompatibilní API, funguje: samotné OpenAI, Groq,
OpenRouter, Together, Azure OpenAI, LM Studio, Ollama a další řešení,
která podporují stejný wire protokol.

Tři přepisová backendy jsou integrovány nativně, protože jejich API
nejsou kompatibilní s OpenAI: Google Gemini, ElevenLabs Scribe a
Speechmatics.

Lze nakonfigurovat více poskytovatelů. Profil zpracování volí poskytovatele
a model pro každý krok. Ruční přepis používá výchozí nastavení účtu, zatímco
ruční shrnutí lze spustit s libovolným dostupným profilem.

<span id="adding-a-provider" />

## Přidání poskytovatele

**Nastavení → AI poskytovatelé → Přidat poskytovatele** otevře dialog s přednastaveným
seznamem. Každá předvolba automaticky vyplní `baseURL`, výchozí model a
nápovědu k tomu, který API endpoint by měl používat pracovník přepisu:

- **Whisper-style** (`/v1/audio/transcriptions`, multipart upload) —
  klasický rozhraní OpenAI Whisper. Používají ho OpenAI, Groq Whisper, Together
  Whisper, LM Studio, Ollama.
- **Chat-style** (`/v1/chat/completions` s částí obsahu `input_audio`) —
  pro poskytovatele, kteří nabízejí LLM s audio vstupem místo dedikovaného API pro přepis.
  Využívá OpenRouter směrující Gemini / GPT-audio / Voxtral.
- **Gemini-style** (`generateContent` s inline audio daty) —
  nativní Google Gemini API. Používá předvolba Google Gemini.
- **Scribe-style** (`/v1/speech-to-text`, multipart upload, autentizace
  přes `xi-api-key`) — nativní API ElevenLabs. Používá předvolba ElevenLabs.
- **Speechmatics-style** (`POST /v2/jobs`, následně polling, stažení) —
  Speechmatics Batch job API. Používá předvolba Speechmatics.

Vyberte předvolbu, vložte svůj API klíč, zvolte výchozí model, uložte. Postup opakujte pro další poskytovatele.

## Referenční přehled předvoleb

| Předvolba      | Základní URL                                     | Poznámky                                                            |
| -------------- | -----------------------------------------------  | ------------------------------------------------------------------- |
| OpenAI         | *(prázdné, defaultně api.openai.com)*            | Produkční kvalita; `whisper-1`, `gpt-4o-transcribe`             |
| Groq           | `https://api.groq.com/openai/v1`             | Bezplatné Whisper API, velmi rychlé                                     |
| OpenRouter     | `https://openrouter.ai/api/v1`               | Přepis ve stylu Chat; mnoho summarizačních modelů na jeden klíč   |
| Together AI    | `https://api.together.xyz/v1`                | Úsporné, široký výběr modelů                                         |
| Google Gemini  | *(prázdné, nativní Google API)*                   | Přepis ve stylu Gemini; pouze přepis                                 |
| ElevenLabs     | *(prázdné, defaultně api.elevenlabs.io)*         | Přepis ve stylu Scribe, volitelné označení mluvčích; pouze přepis   |
| Speechmatics   | *(prázdné, automatické směrování asr.api.speechmatics.com)* | Přepis typu batch job, volitelné označení mluvčích; pouze přepis    |
| Azure          | `https://<resource>.openai.azure.com/...`    | Soulad s korporátními požadavky, URL vázaná na nasazení             |
| LM Studio      | `http://localhost:1234/v1`                   | Lokální, 100% offline                                               |
| Ollama         | `http://localhost:11434/v1`                  | Lokální, snadná správa modelů                                       |
| Vlastní        | *(libovolné)*                                    | Jakýkoli další OpenAI-kompatibilní poskytovatel                     |

Předvolby LM Studio a Ollama ve výchozím stavu používají `http://localhost`. Zevnitř
kontejneru Docker je `localhost` samotný kontejner, ne hostitelský
stroj — použijte `http://host.docker.internal:<port>` na Mac/Windows, nebo
Docker bridge IP na Linuxu, abyste se dostali na AI server běžící na
hostiteli. Pokud provozujete Ollamu ve stejné síti Docker jako Chatterbox, použijte
název služby (`http://ollama:11434/v1`).

## Volba modelů

Seznam předvoleb obsahuje předvybranou sadu známých ID přepisových
modelů pro každý poskytovatel. Pokud API zpřístupňuje strukturovaná metadata
o schopnostech (aktuálně pouze OpenRouter), dialog Přidat/Upravit umí načíst
aktuální seznam modelů, které podporují audio. U ostatních poskytovatelů
rozhoduje o možnostech nabídky předvybraný seznam, a možnost
**Vlastní…** umožňuje zadat ID ručně pro nové modely, které ještě nejsou
při vydání této dokumentace v oficiálním seznamu.

Sumarizace je volnější — funguje libovolný chatovací model, který
splňuje shape OpenAI `chat/completions`. Vyberte model rychlý a levný
(např. `gpt-4o-mini`, `llama-3.1-70b-versatile`), pokud nemáte
konkrétní důvod použít větší model.

### ElevenLabs Scribe

Předvolba nabízí `scribe_v2` (výchozí), `scribe_v2_medical` a
legacy `scribe_v1`. Diarizace je volba při požadavku, nikoli samostatný model,
takže v nabídce je možnost **scribe_v2 (speaker labels)**,
uložená jako `scribe_v2+diarize`. Při aktivní volbě budou přepisy
ve formě `speaker_0: …` řádků, což je stejná struktura, jakou Chatterbox ukládá
u diarizovaného modelu OpenAI, a pracovní stanice zobrazí tyto přepisy
jako dialog místo souvislého textu. Viz [Jak se přepisy a souhrny zobrazují](#how-transcripts-and-summaries-are-displayed).

Pole **Base URL** nechte prázdné pro použití `api.elevenlabs.io`. Pokud chcete držet
audio v určité oblasti, nastavte místo toho hostitele s požadovanou
lokalitou, například `https://api.eu.residency.elevenlabs.io`. Koncová `/v1` je
volitelná.

Zvuk je nahráván přesně tak, jak je uložen. Mono Opus re-encode,
který drží příliš velké nahrávky pod 25 MiB OpenAI limit, je u Scribe
vynechán, protože Scribe akceptuje i vícagigabajtové nahrávky – takže
dlouhá setkání jdou do modelu v plné kvalitě.

Scribe v2 a v2 Medical dostávají seznam jmen ze [Almanachu](./almanac),
max. 500 položek, které jsou zasílány jako keyterms. Viz také
[Jména z Almanachu](./almanac#names-from-the-almanac). ElevenLabs
účtuje keyterms jako doplněk k hodinové sazbě.

ElevenLabs je pouze pro přepis. Nepodporuje `chat/completions` endpoint,
takže mějte druhého poskytovatele pro výchozí sumarizaci.

### Speechmatics

Předvolba nabízí `enhanced` (výchozí, nejvyšší přesnost), `standard`
(rychlejší a levnější), a `melia-1`, což je vícejazyčný model, který
sám detekuje jazyk a přepíná mezi jazyky. Stejně jako u Scribe je diarizace
nastavení v požadavku, ne samostatný model – každá předvolba má tedy
i variantu **(speaker labels)** v rozbalovací nabídce, uloženou jako `enhanced+diarize`
a další. Při výběru těchto variant jsou přepisy ve formátu `speaker_1: …`
řádků a pracovní stanice je zobrazí jako dialog — viz
[Jak se přepisy a souhrny zobrazují](#how-transcripts-and-summaries-are-displayed).
Nativní označení `S1` od Speechmatics je při zpracování změněno na `speaker_1`,
aby byly označení konzistentní s ostatními poskytovateli; jména vzniklá
identifikací mluvčího jsou zachována.

Stejná jména z Almanachu jsou do Speechmatics posílána jako vlastní
slovník, a to včetně tvarů, pod kterými byla dříve špatně rozpoznána.

Vaše **Výchozí jazyk pro přepis** je předáván jako jazykový kód. Pokud jej
nemáte nastavený, Chatterbox požádá o `auto` a nechá Speechmatics
jazyk rozpoznat. Výjimkou je `melia-1`: přijímá pouze `multi`,
takže nastavení jazyka se při jejím výběru ignoruje.

Pole **Base URL** ponechte prázdné pro použití `asr.api.speechmatics.com`, který směruje
do nejbližší oblasti. Pokud chcete zajistit umístění dat v konkrétní oblasti,
nastavte místo toho regionálního hostitele — `https://eu2.asr.api.speechmatics.com`,
`https://us1.asr.api.speechmatics.com`, `https://au1.asr.api.speechmatics.com`
atd. Koncová `/v2` je volitelná.

Batch je asynchronní API: Chatterbox nahraje audio jako úlohu, poté se
každé 3 sekundy dotazuje na stav, stáhne přepis při dosažení `done`
a následně úlohu smaže, aby audio a přepis nezůstaly na serverech
Speechmatics čekající na vypršení retenční lhůty. Celé čekání
je omezeno na `WHISPER_REQUEST_TIMEOUT_MS` (výchozí 60 minut) — zvyšte limit,
pokud přepisujete delší nahrávky.

Audio je nahráno přesně tak, jak je uložené; mono Opus re-encode
omezující velikost pod limit OpenAI 25 MiB je i zde vynechán, stejně jako u Scribe.

Speechmatics je pouze pro přepis — nemá `chat/completions`
endpoint, takže si ponechte zvláštního poskytovatele jako výchozí pro sumarizaci.

## Co je předáváno poskytovateli

Poskytovateli je zasílán zvukový záznam v otevřeném formátu (pro přepis)
a text přepisu v otevřeném formátu (pro sumarizaci). ElevenLabs Scribe v2
a Speechmatics obdrží s audiem až 500 jmen z vašeho Almanachu (viz
[Jména z Almanachu](./almanac#names-from-the-almanac)).

Požadavek na shrnutí obsahuje také údaje potřebné pro krok úkolů: efektivní
čas položky (pro převod „do pátku“ na konkrétní datum), přijaté zmínky úkolů
u této položky a možné dřívější úkoly ze stejného rozsahu složek. Model tak
může navrhnout shodu, dokončení, změnu termínu, zrušení nebo předání. Posílají
se pouze úkoly viditelné v daném rozsahu zpracování, a to poskytovateli
zvolenému profilem použitým pro shrnutí.

Hraniční bod důvěry je právě vámi zvolený poskytovatel.
Šifrování uložených dat u aplikace Chatterbox chrání databázi, nikoliv síťový přenos
směrem k AI poskytovateli — viz
[Šifrování uložených dat](../reference/encryption-at-rest) pro přesný
seznam toho, na co se tato vrstva vztahuje a na co nikoliv.

Pokud potřebujete toto důvěrné rozhraní minimalizovat, provozujte lokálního
poskytovatele (LM Studio nebo Ollama) na stejném zařízení jako instanci s vlastním hostingem.
Přepis i sumarizace pak zůstávají kompletně na vašem hardwaru.

## Volba poskytovatele pro spuštění

V **Nastavení → Profily** zvolte poskytovatele a model pro každý krok profilu
zpracování. Výchozí nastavení složky určuje profil nové položky. U ručního
shrnutí vyberte vedle tlačítka **Shrnout** libovolný dostupný profil. Chcete-li
přepis zopakovat s jiným poskytovatelem, změňte nejprve výchozí nastavení účtu
nebo profil položky a potom spusťte **Přepsat** či **Přepsat znovu**.

## Jak se přepisy a souhrny zobrazují

**Souhrny jsou v Markdownu.** Model je požádán o JSON objekt a
hodnota `summary` v něm je v Markdownu a jako taková je i vykreslena:
nadpisy, odrážky, číslované seznamy, tučný text, odkazy a tabulky jsou
podporovány. Pokyn k tomuto formátování je připojen ke každému promptu,
včetně těch vlastních, takže ve svých proměnných nemusíte formát výslovně
zmiňovat.

JSON obálka zůstává prostý objekt bez jakýchkoli code bloků.
Pokud model požadavek ignoruje a odpoví souvislým textem, odpověď se
zobrazí, nevyřazuje se – a protože je interpretována jako Markdown,
většinou se čte správně.

Surový HTML kód v souhrnu je vypouštěn, nebude zobrazen.

**Diarizované přepisy se zobrazují jako dialog.** Když přepis pochází
z endpointu s rozpoznáním mluvčích, pracovní stanice zobrazí jeden blok
na každé vystoupení s jménem mluvčího nad ním (barevně odlišené),
seskupené podle mluvčího. Týká se to
`gpt-4o-transcribe-diarize`, `scribe_v2+diarize`, modelů
`+diarize` od Speechmatics a přepisů importovaných z Plaud.

Každý jiný přepis se zobrazuje stejně jako dříve, tedy prostý text.
Je to záměr, nikoliv omezení: Gemini a poskytovatelé typu chat mají pokyn
neuvádět jména mluvčích, takže pokud se v přepisu vyskytne řádek typu `Note: send the deck`,
nebude nikdy zaměněn s mluvčím "Note". Diarizovaný přepis, který nakonec
žádné označení mluvčích neobsahuje — což se stane, pokud model najde jen
jeden hlas — se také zobrazí jako prostý text místo dialogového zobrazení
s jedním anonymem.

Jména mluvčích se zobrazují přesně tak, jak je poskytovatel dodal: `speaker_0`
je zobrazeno jako `Speaker 0`, ale nedochází k přečíslování ani přejmenování.
Souhrny uvádějí tato označení přesně podle přepisu, takže zmíněný `speaker_0`
v souhrnu skutečně odkazuje na entitu v přepisu.

<span id="auto-summarize-after-transcription" />

## Automatická shrnutí v profilu

Otevřete **Nastavení → Profily**, upravte profil a u kroku shrnutí zapněte
**Spouštět automaticky**. Zařazená položka dosáhne tohoto kroku po přepisu
a případném čekání na kontrolu Učení. Profil určuje instrukce shrnutí, jazyk
a formát výstupu, poskytovatele, rozpoznání úkolů a vícekrokové zpracování.

Tato cesta je volitelná a stojí nejméně jedno volání poskytovatele AI na
položku. Vícekrokové shrnutí stojí více. Ruční přepis neobchází pořadí profilu:
další automatické kroky pokračují podle profilu přiřazeného položce.

Automatické shrnutí vyžaduje poskytovatele pro rozšíření vybraného v profilu.
Mynah slouží pouze k přepisu, takže hostovaný účet používající jen Mynah
potřebuje pro krok shrnutí dalšího poskytovatele.

<span id="cost-guardrails" />

### Cenové limity

Automatické shrnutí obvykle znamená jedno volání LLM. U chatovacích modelů
za `$0.15-$5 / 1M input tokens` a typických přepisech o 1–2 tisících tokenech
stojí jediné shrnutí zlomek centu, ale velký import nebo dražší model mohou
náklady zvýšit. Dva mantinely:

- **Hodinový limit na uživatele.** Požadavky auto-souhrnu jsou omezeny
  pomocí `AUTO_SUMMARY_RATE_LIMIT_PER_HOUR` (výchozí `60`). Po vyčerpání
  limitu čeká práce pipeline za odloženými úlohami. Přepis zůstane uložen
  a odložení kvůli limitu nevyvolá `summary.failed`. Ruční shrnutí tento
  limit neomezuje.
- **Zvolte model v profilu.** Každý krok shrnutí výslovně určuje
  poskytovatele a model. Chatterbox tiše nenahrazuje jiný chatovací model.

<span id="stale-summaries-on-re-transcribe" />

### Neaktuální souhrny po opakovaném přepisu

Po **opakovaném přepisu** se staré shrnutí a pozdější výsledky pracovního
postupu označí jako **Zastaralé**. Pipeline znovu vytvoří automatické kroky
zapnuté v přiřazeném profilu. Pouze ručně vytvořený výsledek zůstane viditelný
jako zastaralý, dokud jej znovu nespustíte.

<span id="failure-semantics" />

### Selhání a jejich projevy

Selhání je izolované: pokud volání shrnutí selže, přepis zůstane uložen,
`transcription.completed` se stále odešle a `summary.failed` oznámí skutečnou
chybu shrnutí. Ruční akce **Shrnout** zůstává dostupná. Odložení kvůli limitu
není selhání a `summary.failed` nevyvolá.
