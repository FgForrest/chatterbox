Klepna ověřuje každou proměnnou prostředí pomocí schématu Zod v
`src/lib/env.ts` při startu procesu. Nesprávně nastavené prostředí způsobí
pád serveru s přesnou chybovou zprávou namísto spuštění v poškozeném
stavu — to je záměrné. Tato stránka slouží jako zdroj pravdy
pro instalaci s vlastním hostingem.

<span id="required-at-runtime" />

## Povinné za běhu

Tyto proměnné musí být nastavené pokaždé, když server skutečně běží (vývoj i produkce).
Jsou volitelné ve vrstvě **sestavení**, aby `next build`
nezávisel na produkčních tajemstvích.

| Proměnná                   | Typ      | Poznámky                                                                 |
| -------------------------- | -------- | ------------------------------------------------------------------------ |
| `DATABASE_URL`              | string   | Připojovací řetězec k Postgresu                                         |
| `BETTER_AUTH_SECRET`        | string   | Alespoň 32 znaků; podepisuje cookies s relací                          |
| `APP_URL`                   | URL      | Veřejný původ (např. `https://chatterbox.example.com`)                    |
| `ENCRYPTION_KEY`            | hex(64)  | Přesně 64 hex znaků (32 bajtů); viz [Šifrování uložených dat](../reference/encryption-at-rest)|

## Volitelné ovladače

| Proměnná                            | Výchozí hodnota                      | Efekt                                                                                                             |
| ------------------------------------ | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `DISABLE_REGISTRATION`              | `false`                            | Při `true` je registrace odmítnuta na straně serveru a stránka `/register` je zakázána. Stávající uživatelé dál fungují. S [jednotným přihlašováním](./sso) se mohou přihlásit pouze existující účty. |
| `DISABLE_UPDATE_CHECK`              | `false`                            | Při hodnotě `true` patička nikdy nekontroluje u `api.github.com` nové vydané verze.                                 |
| `DOCS_REPOSITORY`                   | `FgForrest/chatterbox`             | GitHub repozitář (`owner/name`), na který směřují odkazy **Upravit na GitHubu** v dokumentaci. Čte se při sestavování dokumentace: předává se jako argument sestavení Dockeru. |
| `SELF_HOST_MODE`                    | `shared`                           | `shared` umožňuje úroveň Organizace; `local` drží každý účet striktně soukromě.                           |
| `ORG_ACCOUNT_EMAIL`                 | nenastaveno                          | Při `ORG_ACCOUNT_PASSWORD` povolí úroveň Organizace: sdílenou stromovou strukturu složek a jeden účet organizace, který ji spravuje. Nesmí odpovídat e-mailu žádného stávajícího uživatele. |
| `ORG_ACCOUNT_PASSWORD`              | nenastaveno                          | Heslo účtu organizace (alespoň 12 znaků). Při každém startu se opětovně nastavuje. Volitelné při jednotném přihlašování, kde účet nemá interaktivní přihlášení. |
| `ORG_ACCOUNT_NAME`                  | `Organization`                     | Zobrazované jméno účtu organizace.                                                                                |
| `ORG_PROVIDER_CALLS_PER_MEMBER_PER_HOUR` | `60`                         | Nejvyšší počet volání, která může jeden člen provést u každého poskytovatele AI Organizace v jednom hodinovém okně. Ostatní členové mají samostatné limity. |
| `CHATTERBOX_VERSION`             | `latest`                           | Čte pouze Docker Compose, ne aplikace. Určuje, které značky obrazů Compose stahuje.                                  |
| `RIFFADO_VERSION`                | nenastaveno                        | Zastaralá po dobu jednoho vydání. Použije se pouze tehdy, když `CHATTERBOX_VERSION` není nastavena.                |
| `WEBHOOKS_REQUIRE_PUBLIC_TARGETS`   | `false`                            | Při `true` musí být webhook URL v HTTPS a řešit na veřejné IP adresy. Užitečné, když Vaše instance je přístupná ostatním. |
| `RATE_LIMIT_TRUST_PROXY_HEADERS`    | `false`                            | Při hodnotě `true` věřit `X-Forwarded-For` pro rozdělování limitů počtu požadavků. Bezpečné jen za reverzní proxy, která záhlaví přepisuje. |
| `RATE_LIMIT_CLIENT_IP_HEADER` | nenastaveno | Pro limity podle IP (vyžaduje `RATE_LIMIT_TRUST_PROXY_HEADERS=true`) a seznam povolených IP administrace čte pouze toto záhlaví. U `x-forwarded-for` bere poslední položku. Jiné záhlaví jako náhradu nezkouší. |
| `API_TOKEN_HASH_SECRET`             | pokud není, použije `BETTER_AUTH_SECRET` | Alespoň 32 znaků. HMAC klíč pro hashování osobních API tokenů a uložených vyhledávacích hashů. Nastavte samostatně pro rotaci hashů tokenů bez rotace tajného klíče relací. Docker Compose ji nepředává: nastavení na existující instalaci zneplatní všechny API klíče, klíče pro nahrávání a uložené vyhledávací hashe, proto ji do `environment:` aplikace přidejte jen u nové instalace. |

Nastavení `RATE_LIMIT_TRUST_PROXY_HEADERS=true` bez proxy,
která přepisuje přeposílací záhlaví, umožní klientům falšovat vlastní IP adresy
a zcela obejít omezení počtu požadavků. Pokud si nejste jistí, že Vaše proxy tato záhlaví
přepisuje/maže, ponechte nenastaveno.

Nastavte `RATE_LIMIT_CLIENT_IP_HEADER=x-real-ip`, pokud Vaše proxy přepisuje
pouze `X-Real-IP`. Klientem dodaná záhlaví `CF-Connecting-IP` a
`X-Forwarded-For` pak nemají vliv. Při volbě `x-forwarded-for` Klepna použije
poslední položku, kterou musí důvěryhodná proxy připojit nebo přepsat.
Chybějící či prázdné zvolené záhlaví znamená neznámou IP adresu; jiné záhlaví
se nezkouší. Bez této volby limity zachovávají původní pořadí:
`CF-Connecting-IP`, `X-Real-IP`, potom první neprázdnou položku
`X-Forwarded-For`. Administrace bez této volby zachovává své původní pořadí
s XFF na prvním místě.
U `x-forwarded-for` je poslední položka klientem pouze tehdy, když je důvěryhodná proxy jediným prostředníkem před aplikací; při více proxy zvolte záhlaví, které nastavuje poslední proxy, například `x-real-ip`.
Stávající instalace nevyžadují žádnou změnu.
Pro zapnutí předejte novou proměnnou v `environment:` služby aplikace
a nastavte ji v `.env`.

Přiložený `docker-compose.yml` předává aplikaci všechny proměnné z této
stránky kromě `API_TOKEN_HASH_SECRET` a těch, které se čtou při sestavení.
Vlastní soubor Compose předává jen to, co uvádí jeho `environment:`, proto při
aktualizaci zkopírujte nové položky ze souboru z vydání.

## Úložiště

| Proměnná                | Výchozí     | Efekt                                                               |
| ----------------------- | ----------- | ------------------------------------------------------------------- |
| `DEFAULT_STORAGE_TYPE`  | `local`     | `local` nebo `s3`. Výchozí pro nové uživatele; možnost individuálně změnit v UI.|
| `LOCAL_STORAGE_PATH`    | `./storage` | Systémová cesta k souborům, pokud `DEFAULT_STORAGE_TYPE=local`.                  |
| `S3_ENDPOINT`           | —           | URL koncového bodu. Prázdné pro AWS S3.                                    |
| `S3_BUCKET`             | —           | Název kontejneru.                                                        |
| `S3_REGION`             | —           | Region (`auto` na R2).                                            |
| `S3_ACCESS_KEY_ID`      | —           |                                                                   |
| `S3_SECRET_ACCESS_KEY`  | —           |                                                                   |
| `BACKUP_STORAGE_PATH`   | —           | Cesta v systému pro archivy záloh. Pokud není, ukládají se vedle nahrávek. S přiloženým souborem Compose je to cesta hostitele, připojená v kontejneru na `/backups`. |

Viz [S3-kompatibilní úložiště](./storage-s3) pro šablony konfigurací jednotlivých poskytovatelů.

`BACKUP_STORAGE_PATH` stojí za nastavení, pokud používáte **Nastavení →
Export/Záloha → Frekvence záloh**. Bez něj se každý plánovaný archiv
zápisuje do stejného místa jako zvuková data, která obsahuje – složka se
tak zhruba zdvojnásobí a záloha sdílí disk s originálem. Nastavte na samostatné
úložiště (externí disk, NAS), a archivy půjdou tam bez ohledu na systém úložiště nahrávek.
Vždy se uvádí lokální systémová cesta, včetně případů, kdy instance běží na S3: záloha,
kterou nelze bez běžící aplikace přečíst, není opravdu záloha.
Archivy vytvořené před jejím nastavením zůstanou na původním místě a už je
nelze stáhnout; do sedmi dnů vyprší.

| `BACKGROUND_SYNC_INTERVAL_MS`      | `300000`     | Jak často běží synchronizace na pozadí (60000 až 3600000). Uživatel synchronizovaný v posledních čtyřech minutách se vždy přeskočí. |
| `PLAUD_SYNC_RATE_LIMIT_PER_MINUTE` | `10`         | Kolik požadavků na synchronizaci smí jeden uživatel poslat za minutu (1 až 600). |
| `WEBSHARE_API_KEY`                 | —            | Směruje požadavky do cloudu diktafonu přes proxy Webshare, pro hostitele, jejichž adresa se tam přímo nedostane. |
| `PLAUD_PROXY_SCOPE`                | `all`        | `all` posílá přes proxy i stahování zvuku; `api-only` šetří data proxy. Bez `WEBSHARE_API_KEY` nemá vliv. |
| `VIDEO_UPLOAD_MAX_BYTES`           | `4294967296` | Největší nahrávané video (4 GiB). Uchová se jen oddělený zvuk. Zvukové soubory zůstávají omezené na 500 MB. |
| `WHISPER_MAX_BYTES`                | `25165824`   | Vstupy přepisu ve stylu OpenAI nad tuto velikost se překódují do mono Opus. Nejvýše limit poskytovatele 25 MiB. |
| `WHISPER_COMPRESS_BITRATE_KBPS`    | `12`         | Počáteční datový tok tohoto překódování; podle potřeby klesá. |
| `WHISPER_REQUEST_TIMEOUT_MS`       | `3600000`    | Časový limit jednoho požadavku na přepis (60 minut). |
| `AUTO_SUMMARY_RATE_LIMIT_PER_HOUR` | `60`         | Kolik automatických shrnutí, témat a běhů Učení smí jeden uživatel spustit za hodinu (1 až 600). Ruční spuštění se neomezuje. |

| Proměnná                      | Výchozí | Efekt                                                                                      |
| ----------------------------- | ------- | ----------------------------------------------------------------------------------------- |
| `GOOGLE_CLIENT_ID`            | —       | ID klienta OAuth („Web application“ klient).                                                |
| `GOOGLE_CLIENT_SECRET`        | —       | Tajný klíč klienta OAuth.                                                                       |
| `GOOGLE_PICKER_API_KEY`       | —       | Prohlížečový API klíč pro Google Picker. Omezte pouze na Picker API a svou `APP_URL`.     |

| `GOOGLE_WORKSPACE_DOMAINS`    | —       | Čárkou oddělené Workspace domény, které smějí připojit účet. Pokud není, může kdokoliv koho schválí obrazovka souhlasu. |

<span id="single-sign-on-openid-connect" />

## Jednotné přihlášení (OpenID Connect)

Pouze vlastní hosting; ignoruje se, když `IS_HOSTED=true`. Při nastavení
prvních tří je poskytovatel identity jediný způsob přihlášení: přihlášení
e-mailem/heslem, registrace a obnovení hesla jsou vypnuty. Viz
[Jednotné přihlášení](./sso).

| Proměnná               | Výchozí                | Efekt                                                                                       |
| ---------------------- | ---------------------- | ------------------------------------------------------------------------------------------- |
| `OIDC_ISSUER_URL`      | —                      | URL vydavatele; koncové body se berou z jeho `/.well-known/openid-configuration`. `https`, nebo `http` pouze na interním hostu. |
| `OIDC_CLIENT_ID`       | —                      | ID důvěryhodného klienta.                                                            |
| `OIDC_CLIENT_SECRET`   | —                      | Tajný klíč klienta.                                                                              |
| `OIDC_PROVIDER_NAME`   | `SSO`                  | Zobrazené na tlačítku: „Přihlásit se pomocí …“.                                              |
| `OIDC_SCOPES`          | `openid profile email` | Oddělené mezerami nebo čárkami. `openid` je vždy vyžadován.                                 |
| `OIDC_SESSION_MAX_AGE` | `86400`                | Doba platnosti relace v sekundách (300 až 2592000), neprodlužuje se používáním.             |

<span id="external-mcp-server" />

## Externí MCP server

Pouze vlastní hosting; vypnuto při `IS_HOSTED=true`. Vyžaduje [jednotné přihlášení](#single-sign-on-openid-connect)
a `APP_URL`; tokeny jsou ze stejné oblasti. Viz
[Externí MCP server](./mcp) a pro proměnné veřejného vstupu a konektoru
[Claude a Claude Code](./claude).

| Proměnná                   | Výchozí | Efekt                                                                                                  |
| -------------------------- | ------- | ------------------------------------------------------------------------------------------------------ |
| `MCP_AUDIENCE`             | —       | ID klienta chráněných zdrojů s přístupovými rolemi v Keycloaku (např. `chatterbox-mcp`). Pokud není, `/api/mcp` vrací 404. |
| `MCP_ALLOWED_CLIENTS`      | —       | Čárkou oddělená ID klientů (`azp`), která smějí volat. Povinné při nastavení `MCP_PUBLIC_CLIENTS`; jinak bez něj může volat každý klient realmu s požadovanou rolí (při startu se zapíše varování). |
| `MCP_PUBLIC_INGRESS_HEADER`| —       | Hlavička, kterou veřejná reverzní proxy nastaví na přeposlané požadavky (např. `X-MCP-Ingress`); vnitřní cesta ji odebere. Požadavek s ní se obslouží jen pro `MCP_PUBLIC_CLIENTS`. |
| `MCP_PUBLIC_CLIENTS`       | —       | Čárkou oddělená ID klientů obsluhovaná veřejným vstupem (např. `claude`). Vyžaduje `MCP_PUBLIC_INGRESS_HEADER`. |
| `MCP_CONNECTOR_KEYS`       | —       | Čárkou oddělené dvojice `client=klíč` (klíče od 32 znaků): token uvedeného klienta se obslouží jen s `X-API-Key: <klíč>`, hlavičkou požadavku konektoru Claude. Tajné. |
| `MCP_RESOURCE_AUDIENCE`    | `false` | Při `true` přijímá i tokeny, jejichž `aud` je `<APP_URL>/api/mcp` (identifikátory zdrojů v Keycloaku). |
| `MCP_AUDIT_RETENTION_DAYS` | `90`    | Počet dní po které se záznam v tabulce `mcp_access_log` uchovává (1 až 3650).                              |
| `MCP_SERVICE_CLIENTS`      | —       | Čárkou oddělení klienti určení jen pro služby, jejichž označené tokeny jednají v datovém kontextu Organizace. Je-li nastaveno `MCP_ALLOWED_CLIENTS`, musí v něm být každý z nich. Při nastavení (nebo při `AUTHZ_MODE=idp`) je token službou, jen když je jeho klient uveden a realm ho označil; bez nastavení v režimu `local` se token s `client_id` stále považuje za službu (zastaralé). |

| `AUTHZ_VERIFICATION_MAX_AGE`      | `1800`     | Počet sekund, po které se ověřený přístup používá, než se poskytovatel zeptá znovu (nejvýše 3600). |
| `AUTHZ_ADMIN_MAX_AUTH_AGE`        | `28800`    | Počet sekund od posledního přihlášení administrátora u poskytovatele, během nichž smí měnit přístup. |

Čte služba `mail-receiver` (profil compose `mail`):

## Nahrávání schůzek

Výchozí hodnoty, které server posílá propojeným rozšířením [Nahrávání schůzek](../guides/meeting-recorder).
Vše volitelné; bez nastavení se nic nenahrává jedním kliknutím, dokud si to
člověk sám nezapne.

| Proměnná                            | Výchozí | Efekt |
| ----------------------------------- | ------- | ----- |
| `RECORDER_AUTO_RECORD_PLATFORMS`    | —       | Čárkou oddělené platformy, které se nahrávají jedním kliknutím, nebo `all`: `google-meet`, `zoom`, `teams`, `webex`, `slack-huddle`, `whereby`, `jitsi`. |
| `RECORDER_AUTO_STOP_QUIET_SECONDS`  | `180`   | Po kolika sekundách ticha se nahrávání jedním kliknutím samo zastaví (30 až 3600). |
| `RECORDER_NOTICE_TEXT`              | —       | Pravidla nahrávání, která rozšíření jednou zobrazí před zapnutím nahrávání jedním kliknutím. |
| `RECORDER_LOCK_DEFAULTS`            | `false` | Při `true` nelze vypnout platformu, kterou server nastavil na nahrávání jedním kliknutím. |
| `NEXT_PUBLIC_RECORDER_EXTENSION_ID` | zveřejněné rozšíření | ID rozšíření Chrome, se kterým se aplikace propojuje, pro rozšíření, které si sestavujete sami. Čte se při sestavení aplikace, takže platí jen v obrazu, který s ní sami sestavíte. |

<span id="when-values-are-missing" />

## Co když hodnoty chybí

Při startu serveru načítání prostředí provede dva průchody:

1. **Ověření schématu** – typy, formáty, rozsahy. Chyby vyústí v
   vícenásobnou `Environment validation failed:` chybu, která vypíše
   konkrétní pole s problémem.
2. **Kontrola přítomnosti hodnot za běhu** – proměnné požadované za běhu
   (`DATABASE_URL`, `BETTER_AUTH_SECRET`, `APP_URL`, `ENCRYPTION_KEY`)
   se ověří, že nejsou prázdné a mají správnou sílu. Tyto kontroly se přeskakují
   při `next build` (fáze `phase-production-build`), aby
   sestavení uživatelského rozhraní nezáviselo na serverových tajemstvích.

Pokud je hodnota špatná, server odmítne start. To je smluvené chování.
